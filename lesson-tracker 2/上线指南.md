## 开通流程

1. 机构负责人自行注册并登录 [Render](https://dashboard.render.com/)；账号、服务条款和支付方式由负责人确认。不要把密码或银行卡信息发在聊天中。
2. 将本文件所在文件夹的源码放入机构拥有的私有 Git 仓库，根目录需包含 `render.yaml`。不得上传 `data/`、数据库备份或真实家长资料。
3. 在 Render 连接该仓库并通过 Blueprint 读取 `render.yaml`。核对新加坡地区、单个付费 Web Service、1 GB 磁盘和最终费用后再确认创建。
4. 部署成功后，在该服务的 Shell 中执行 `python server.py --create-owner`。按交互提示由负责人输入自己的手机号、姓名和密码。
5. 打开服务实际分配的 HTTPS 网址，以老师账号登录，添加测试学生和测试家长，充值 1 课时，再扣除 0.5 课时。
6. 用另一浏览器登录测试家长账号，核对剩余 0.5 课时，确认不能查看其他学生或修改数据。
7. 设置独立备份位置与备份频率，并完成一次恢复验证后再录入真实学生。

## 重要配置

`render.yaml` 已关闭演示账号并开启安全 Cookie。正式数据库位于 `/var/data/lessons.sqlite3`，必须保留挂载在 `/var/data` 的持久磁盘。不要将演示数据库复制到正式环境。

当前配置时区为 `Australia/Melbourne`，如机构使用其他时区应在 Render 环境变量中调整 `TZ`。

当前版本设计为单个应用实例；不要启用多实例扩容。若学生数量或并发量显著增加，再评估迁移到托管 PostgreSQL。

当前没有短信验证、短信找回或在线支付，手机号是登录名。账号由老师开通，忘记密码由维护人员重设。

## 备份与恢复

在服务 Shell 中创建一致性备份（文件名每次不同）：

```sh
python backup.py /var/data/backups/lessons-YYYY-MM-DD.sqlite3
```

工具采用 SQLite backup API，并校验数据库完整性；不会覆盖已有文件。备份需另存到机构的独立私有存储，同一磁盘内的副本不能代替异地备份。本交付尚未配置定时异地备份。

恢复应由维护人员先停止写入、保留现有数据库完整副本、使用校验过的备份替换数据库，再启动服务验证余额和明细；不能在运行中的数据库上直接覆盖文件。

## 技术交接

- 正式启动：`gunicorn --config gunicorn.conf.py wsgi:application`
- 依赖：`requirements.txt`
- 健康检查：`/health`
- 重新设置账号密码：`python server.py --reset-password`
- 核心测试：`python test_app.py`
- 正式服务器测试：`LESSON_TEST_WSGI=1 python test_app.py`

Render 配置根据其 [Blueprint 文档](https://render.com/docs/blueprint-spec) 编写。正式入口使用 [Gunicorn](https://pypi.org/project/gunicorn/)。平台、套餐和服务版本未来变更时，应重新核对配置。
